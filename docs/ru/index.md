## HTTPS через Jump

Режим **HTTPS через Jump** соединяет два обычных HTTPS CONNECT-прокси:
телефон → промежуточный прокси → конечный прокси → сайт. В основных полях укажите конечный
прокси, а в разделе промежуточного — первое звено. Порт по умолчанию для обоих — 443.
Промежуточный прокси должен разрешать CONNECT к имени и порту конечного прокси; он же разрешает
его имя. На телефоне разрешается только имя промежуточного прокси.

Оба звена используют выбранный TLS-профиль и независимо поддерживают HTTP/1.1 и HTTP/2 CONNECT.
Проверка сертификата и данные Basic Auth настраиваются отдельно для каждого звена; можно
использовать одинаковые имя пользователя и пароль. Проверка подключения и DoH идут через
цепочку. Доступ к локальной сети определяется существующей настройкой обхода. При отказе
звена приложение не подключается к конечному прокси напрямую.

Цепочки сохраняются в JSON версии 8 (`proxy.type: "HTTPS_JUMP"`, первое звено — `proxy.jump`).
Старые версии приложения отклоняют этот формат, чтобы не превратить цепочку в одиночный прокси.
Экспорт ProxyList пропускает цепочки, поскольку поддерживает одиночные HTTPS/MASQUE/SOCKS5-прокси.

## SOCKS5

Выберите тип **SOCKS5**, задайте хост и порт (по умолчанию 1080). Авторизация
необязательна: оба поля пустые либо логин и пароль по 1–255 байт UTF-8 каждый.
Поддерживаются TCP CONNECT и UDP ASSOCIATE. По умолчанию DNS использует выбранный DoH через
прокси; кнопка «Тест» также проверяет HTTP/3 через UDP. Действуют маршрутизация
приложений, IPv6, обход локальных сетей, failover и статистика.

SOCKS5 не шифрует соединение с прокси, включая пароль, и не использует отпечаток
TLS. TLS приложений и DoH сохраняют собственное шифрование. Jump для SOCKS5 не
предусмотрен. JSON использует `proxy.type: "SOCKS5"`; списки прокси —
`socks5://host:1080` или `socks5://user:password@host:1080`.

В GOST UDP включается явно: `gost -L 'socks5://user:password@:1080?udp=true'`.
Объявленный сервером IP и порт UDP-релея должны быть доступны через NAT/firewall.
Нулевой IP заменяется адресом прокси; ответ с именем релея отклоняется без системного
DNS. См. [документацию GOST](https://gost.run/en/tutorials/protocols/socks/).

## Отпечатки и диагностический журнал

Отпечаток HTTPS по умолчанию сейчас соответствует Chrome Android; в будущих версиях
может быть выбран другой браузер. Профиль SSH задаёт баннер клиента и порядок предпочтения
алгоритмов обмена ключами, шифрования и MAC. Эти настройки относятся к соединению с прокси,
а не к браузеру и другим приложениям внутри туннеля. Отпечатки QUIC и требования к ручному
JA3 описаны в [руководстве MASQUE](masque.md).

Размер журнала ограничивает общий объём двух сегментов с ротацией: 1–100 MiB.
При ротации старые события удаляются; очистка журнала удаляет оба сегмента.
Подробности измерений и событий — в [описании метрик соединения](connection-metrics.md).
