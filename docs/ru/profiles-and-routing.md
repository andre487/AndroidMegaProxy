# Профили и маршрутизация

[English](../en/profiles-and-routing.md) · [Все руководства](index.md)

## Профили

В **Настройки → Профили** можно добавить, клонировать, переименовать, переместить или удалить
профиль сервера. Имена, флаги стран и цвета помогают различать серверы. Для сортировки удерживайте
и перетаскивайте профиль или используйте действия перемещения. Выбор другого профиля при
работающем VPN переподключает его.

| Область | Настройки |
| --- | --- |
| Профиль | Транспорт, адреса сервера/Jump, авторизация и доверие, DNS, IPv6, предпочтение HTTP/3, необязательный хост проверки авторизации |
| Общие для профилей | Маршрутизация приложений, обход LAN, отпечатки, авторизация/keepalive/каналы/ротация SSH, failover |
| Локальные, не переносятся | MTU, строгая проверка источника и её уровень, язык, единицы трафика, обновления; разрешения небезопасного DNS остаются локальными для профиля |

Изменения работающего соединения требуют переподключения. Обновление подписки сохраняет текущий
туннель и предлагает **Переподключить**; [владение профилями и правила подписок](subscriptions.md).

## Типы серверов

MegaProxy не предоставляет серверы. Получите профиль у доверенного оператора или настройте
свой сервер через [MegaProxyServer](https://github.com/andre487/MegaProxyServer).

| Тип | Порт по умолчанию | Передача трафика |
| --- | --- | --- |
| HTTPS | 443 | TCP через HTTP/1.1 или мультиплексированный HTTP/2 CONNECT; опциональное предпочтение HTTP/3 |
| SOCKS5 | 1080 | TCP CONNECT и UDP ASSOCIATE; без шифрования соединения с прокси |
| MASQUE α | 443 | Экспериментальная передача TCP и UDP через HTTP/3; [совместимость и ограничения](masque.md) |
| SSH | 22 | TCP через каналы `direct-tcpip` |
| HTTPS / SSH через Jump | 443 / 22 для каждого звена | Телефон → промежуточный сервер → конечный прокси → сайт |

Это возможности обычного трафика; [для DNS действуют отдельные правила](dns.md).
TLS приложений остаётся сквозным: MegaProxy не устанавливает CA и не расшифровывает его.

### HTTPS и Jump

В основных полях задайте конечный прокси. Для **HTTPS через Jump** укажите первое звено в
разделе промежуточного HTTPS-прокси. Оно должно разрешать CONNECT к имени и порту конечного
прокси и само разрешает его имя; на телефоне разрешается только имя первого звена. Для каждого
звена настраиваются проверка TLS и Basic Auth либо используются одинаковые данные авторизации.
Оба применяют выбранный отпечаток TLS и независимо согласуют HTTP/1.1 или HTTP/2.
При отказе звено никогда не обходится прямым подключением.

**Предпочитать HTTP/3 α** по умолчанию выключено. Сначала пробуется MASQUE на том же хосте/UDP-порту,
при недоступности — HTTPS; ошибки авторизации и сертификата завершают подключение. Для Jump
нужны MASQUE и подходящий MTU датаграмм на обоих звеньях, иначе вся цепочка использует HTTPS/TCP.
При переходе на HTTPS/TCP обычный UDP блокируется с предупреждением. Явный MASQUE не использует fallback.

### Скрытые ошибки авторизации

Некоторые прокси вместо отказа авторизации показывают сайт-приманку (decoy) или задерживают ответ. По одному таймауту или HTML нельзя достоверно определить наличие decoy.

Для обычного профиля **HTTPS** доступно необязательное поле **Хост проверки авторизации**. Укажите предоставленный оператором knock-хост без URL, пути и порта. При диагностике HTTPS по TCP приложение отправляет через прокси CONNECT к этому хосту на порт 443 с учётными данными профиля; проверка ограничена пятью секундами. Явный `407` подтверждает отказ авторизации и останавливает тест. `200` означает только принятие CONNECT; после него выполняется обычная сквозная проверка HTTPS. Остальные статусы и таймауты не доказывают ошибку логина или пароля.

При пустом поле дополнительного запроса нет. В JSON используется
`profiles[].proxy.knockHost`; старый `profiles[].browser.knockHost` читается только
при отсутствии общего поля. Явно пустое общее поле отключает проверку, даже если
старый псевдоним заполнен. Остальные браузерные настройки игнорируются.

Проверка относится к обычному HTTPS по TCP, а не HTTPS с Jump или выбранному HTTP/3. Изменение диагностического хоста не переподключает работающий VPN; новый тест использует его для того же действующего адреса прокси, сохраняя действующие учётные данные. Дополнительных проверок пакетов нет.

Общий журнал диагностики содержит события `proxy_auth_probe`: начало, пропуск, принятие CONNECT, отказ или неопределённый результат, HTTP-статус, время и безопасный класс ошибки. Хосты проверки и прокси, IP, логины, пароли и содержимое ответов в эти события не попадают.

### SOCKS5

Оставьте оба поля авторизации пустыми или задайте логин и пароль по 1–255 байт UTF-8 каждый.
**Соединение с прокси и пароль не шифруются**; TLS приложений и DoH сохраняют собственное шифрование.
Браузерные отпечатки TLS не применяются. Jump для SOCKS5 не предусмотрен.

В GOST включите UDP: `gost -L 'socks5://user:password@:1080?udp=true'`.
Объявленный UDP-релей должен быть доступен через NAT/firewall. Нулевой адрес заменяется адресом
прокси; нулевой порт или имя релея отклоняются без системного DNS.

### SSH и Jump

Используйте пароль или импортируйте приватный ключ без парольной защиты. Зашифрованные ключи
не поддерживаются. Перед доверием сравните отпечаток SSH-ключа сервера с данными оператора;
для Jump и конечного сервера доверие хранится отдельно. Отключение проверки ключа SSH или
сертификата прокси допускает подмену сервера.

**SSH через Jump** достигает конечного SSH-сервера через первое SSH-соединение, с отдельными
паролями/ключами или общей авторизацией. В **Настройки → Цифровые отпечатки** выбираются автоматическая,
только парольная или только ключевая авторизация, интервал keepalive, лимит каналов и ротация
сеанса по времени/трафику. Ротация ждёт завершения активных каналов. Профиль SSH меняет баннер
клиента и предпочтение алгоритмов, а не приложения внутри туннеля.

## Маршрутизация и проверка приложения-источника

В **Настройки → Раздельное туннелирование** выберите все приложения или укажите нужные.
Переключатель MegaProxy и его флажок в списке — один выбор. MegaProxy включён по умолчанию;
явное исключение сохраняется, и его диагностика, подписки и другие запросы идут по обычной сети.
Обход LAN отправляет поддерживаемый локальный трафик напрямую и не является fallback при отказе
прокси. IPv6 включается отдельно в профиле.

**Строгая проверка источника** по желанию проверяет владельца TCP/UDP-трафика на Android 10+.
По умолчанию выключена и применяется при переподключении. Стандартный уровень кеширует разрешение
UDP до секунды для живого потока, расширенный проверяет каждую исходящую датаграмму. Оба проверяют
новые TCP-соединения, блокируют неизвестных владельцев и ping в TUN. Возможны задержки установки
TCP-соединений, замедление UDP и нарушения работы приложений; [поведение и ограничения](source-validation.md).
**Видимость VPN** показывает работающий уровень.

## Резервные подключения и Always-on

**Настройки → Переключение при сбое** позволяют пробовать выбранные или все профили после
повторных сбоев соединения; по умолчанию отключены. Нужны хотя бы два подходящих профиля.
Ошибки авторизации, сертификата и конфигурации не вызывают переключение. Автоматическая смена
может изменить внешний IP и видимую страну; уведомление показывает активный профиль.
[Ограничения определения сбоев](connection-metrics.md).

В **Настройки → Постоянный VPN** выберите стартовый профиль, затем включите Always-on и при
необходимости **Блокировать соединения без VPN** в настройках VPN Android. Смена стартового
профиля при работающем Always-on переподключает его сразу. Ограничения Android/производителя
на фоновую работу и явная принудительная остановка продолжают действовать. Если Android ограничивает
VPN в фоне, откройте **Настройки → Настройки батареи**.

## Импорт, экспорт и локальные настройки

Импортируйте MegaProxy JSON, ProxyList, FoxyProxy JSON или поддерживаемый текст SuperProxy.
Импорт сообщает об игнорируемых браузерных и неизвестных полях. JSON версии 8 сохраняет постоянные
ID профилей и переносимые настройки; явно неподдерживаемый транспорт отклоняется. ProxyList
экспортирует только одиночные HTTPS/MASQUE/SOCKS5-прокси; для SSH, Jump и остальных настроек нужен JSON.

Пароли и приватные ключи SSH включаются в экспорт отдельно. Пропущенные секреты сохраняют
прежние значения только для того же сервера/аккаунта; явно пустые очищают их. Токены в URL
остаются в JSON даже без паролей. Экспортированные пароли/ключи читаемы: защищайте файл.
JSON — не полный бэкап приложения. [Схемы и примеры](../../config-schema/).

**Настройки → Единицы трафика** переключают IEC (по умолчанию, степени 1024: KiB/MiB) и SI
(1000: KB/MB) для объёмов и скорости; поля лимитов трафика остаются в MiB. Язык выбирается
отдельно от системной локали чисел и дат. **MTU** хранится локально и применяется при
переподключении; [выбор MTU](connection-metrics.md#mtu-vpn-интерфейса).

**Диагностический журнал** можно просмотреть, экспортировать и очистить; ротация ограничивает
хранение объёмом 1–100 MiB. Обратная связь прикладывает его через выбранное почтовое приложение;
просмотрите отчёт перед отправкой. [Диагностика, скорость и видимость](connection-metrics.md#тест-скорость-и-видимость-vpn)
описывают общий журнал тестов и ограничения измерений; [политика конфиденциальности](../../PRIVACY.md).

Полный перечень переносимых и локальных настроек: [справочник полей](https://github.com/andre487/MegaProxyConfig/blob/main/docs/field-reference.md).
