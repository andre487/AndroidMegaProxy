# Строгая проверка источника

[English](../en/source-validation.md) · [Документация](index.md)

В **Раздельном туннелировании** доступна опция **Строгая проверка источника** для Android 10+.
Применяется при переподключении VPN, по умолчанию выключена, хранится локально и не входит
в экспорт профилей и подписки. При выключенной опции нативный стек использует прежние
обработчики: без запросов UID, кешей проверки и дополнительных проверок пакетов.

Оба уровня проверяют владельца TCP один раз до выхода через прокси или напрямую в LAN.
Это добавляет задержку при установлении соединения; повторных проверок на TCP-данных нет.
UDP, включая DNS, проверяется при создании потока. Для UDP доступны два уровня:

| Уровень | Проверка владельца UDP | Компромисс |
| --- | --- | --- |
| Стандартный (первоначальный выбор) | При создании потока и на первой исходящей датаграмме после фиксированного интервала 1 секунду | Меньше запросов Android API; повторно использованный порт может временно наследовать прежнее разрешение |
| Расширенный | При создании потока и на каждой исходящей датаграмме | Быстрее обнаруживает смену владельца; больше нагрузка и задержка |

Кеш стандартного уровня принадлежит только конкретному живому потоку: он не разделяется
по исходному порту, между адресатами или следующими потоками. Попадания в кеш не продлевают
срок; фоновый таймер не нужен. После истечения срока следующая датаграмма требует новой
проверки до передачи. При отказе поток закрывается. Между проверками сознательно допускается
окно устаревшего разрешения до 1 секунды; этот уровень не равнозначен расширенному.
Ни один уровень не делает запрос владельца и передачу атомарной операцией ядра.

Неизвестный владелец и ошибка API при проверке блокируются. В split-режиме разрешены только
выбранные UID; в глобальном требуется определимый владелец. Приложения с общим UID
неразличимы. Медленные проверки новых потоков идут вне общего цикла TUN с ограничением
64 одновременных проверок; лишние попытки закрываются. Оба уровня могут нарушать работу
приложений и трафика без определимого владельца, например раздачи интернета.
Прямого обхода блокировки нет.

Уровень тоже хранится локально и применяется при переподключении. Ранее включённая опция
без указанного уровня переносится в расширенный режим с сохранением поведения;
при первом включении выбирается стандартный. Видимость показывает фактически работающий
уровень, в том числе когда его смена ещё ожидает переподключения.

Echo (ping) IPv4/IPv6 блокируется до userspace-стека; обычные ошибки ICMP обрабатываются
штатно. Фрагментированный ICMP и IPv6-фрагменты с неопределимым транспортом также блокируются.
ICMP физического соединения не затрагивается. TCP/HTTP-диагностика приложения продолжает
работать. **Проверка видимости** показывает защиту текущего туннеля и необходимость
переподключения. Это статус сеанса, а не проверка атаки из другого приложения;
он не скрывает VPN-интерфейсы и другие системные признаки VPN.
