# DNS

По умолчанию используется DoH. Свой HTTPS URL может содержать домен, IPv4 или IPv6 в квадратных
скобках, порт, путь и параметры. Без пути используется `/`. Сервер должен возвращать двоичный
DoH (`application/dns-message`); HTML, обычный DNS и DoT не подходят. Ошибка TLS/HTTP сама по себе
не доказывает отсутствие DoH.

**Разрешить недоверенные сертификаты DoH** после подтверждения допускает самоподписанные,
просроченные сертификаты и несовпадение имени. Исключение действует только на DoH, не на прокси
или jump. Оно ослабляет аутентификацию сервера: DNS может быть перехвачен.

Чтобы выбрать обычный DNS, локально включите **Небезопасный DNS**. Укажите числовой IPv4 или IPv6
в квадратных скобках, при необходимости порт (по умолчанию 53). Доменное имя не разрешается.

| Режим | Маршрут и шифрование |
|---|---|
| DoH | Через цепочку прокси; HTTPS до DNS-сервера |
| TCP DNS | Через цепочку прокси, включая локальный DNS при обходе LAN; после прокси без шифрования |
| UDP DNS, фактический MASQUE/HTTP3 | Через CONNECT-UDP; до прокси шифруется, после — нет |
| UDP DNS, SOCKS5 | Через UDP ASSOCIATE; SOCKS5 не добавляет шифрование |
| UDP DNS, фактический HTTPS/TCP или SSH | Защищённый от петли прямой сокет вне VPN; без шифрования на всём пути |

Для HTTPS с предпочтением HTTP/3 учитывается фактически выбранный транспорт. Ошибка туннельного
UDP никогда не переключает DNS на прямой UDP. У обычного DNS нет публичных DoH-фолбеков.
Политика IPv6 и отмена действуют во всех режимах. Перехватываются UDP/TCP на порт 53;
собственный шифрованный DNS приложений следует обычной маршрутизации.

Переносимый профиль сохраняет адрес в прежнем строковом поле `dns.customDohUrl` с явной схемой
`https://`, `tcp://` или `udp://`. Для своего сервера используется `dns.provider: "CUSTOM"`, например
`https://dns.example/dns-query`, `tcp://192.0.2.53:53` или `udp://[2001:db8::53]:53`.
Имя поля и схема версии 8 не меняются. Клиенты без поддержки обычного DNS не могут использовать
TCP/UDP-адреса и не должны трактовать их как DoH. Разрешения небезопасных режимов и сертификатов
остаются только на устройстве: экспорт, импорт и подписки не дают такого согласия.
На новом устройстве подтвердите его локально перед подключением.
Обновление или импорт неизменившегося резолвера сохраняет локальные разрешения;
смена резолвера требует нового подтверждения.
Токены в параметрах своего DoH URL остаются в JSON даже при экспорте без паролей.
Такой файл содержит секретные данные.
Начальное разрешение имени прокси происходит до создания VPN; сервисы перечислены в README.

На прокси допускается до 64 DNS-потоков суммарно для перехваченного TCP и UDP. При заполнении
лимита удаляется самый старый завершённый UDP-поток вместе с его TUN-соединением. Потоки
с ожидающими ответами и TCP DNS сохраняются.
Если завершённый UDP-поток нельзя вытеснить, новые потоки сразу отклоняются; остановка VPN закрывает потоки и отменяет их запросы.

Альтернативные DoH-запросы запускаются с интервалом 200 мс: используется первый корректный
ответ, остальные запросы отменяются. При задержке запрос может попасть нескольким настроенным
провайдерам. У CUSTOM и фильтрующих провайдеров фолбеков нет. Начальное разрешение адреса
прокси использует тот же подход со своим списком провайдеров независимо от DNS профиля.
У обычного DNS остаётся только выбранный сервер.

## Строгая проверка источника

В **Раздельном туннелировании** доступна опция **Строгая проверка источника** для Android 10+.
Применяется при переподключении VPN, по умолчанию выключена, хранится локально и не входит
в экспорт профилей и подписки. При выключенной опции нативный стек использует прежние
обработчики: без запросов UID, кешей проверки и дополнительных проверок пакетов.

При включении владелец TCP проверяется до выхода через прокси или напрямую в LAN, UDP —
при создании потока и на каждой исходящей датаграмме, включая DNS, без положительного кеша,
способного пережить Android-сокет. Неизвестный владелец, ошибка API и устаревший сеанс
блокируются. В split-режиме разрешены только выбранные UID; в глобальном требуется
определимый владелец. Приложения с общим UID неразличимы. Запрос владельца и передача —
раздельные операции, а не атомарная гарантия ядра. Медленные проверки новых потоков идут
вне общего цикла TUN с ограничением 64 одновременных проверок; лишние попытки закрываются.
Проверки UDP увеличивают задержку и нагрузку и могут нарушать работу приложений и трафика
без определимого владельца, например раздачи интернета. Прямого обхода блокировки нет.

Echo (ping) IPv4/IPv6 блокируется до userspace-стека; обычные ошибки ICMP обрабатываются
штатно. Фрагментированный ICMP и IPv6-фрагменты с неопределимым транспортом также блокируются.
ICMP физического соединения не затрагивается. TCP/HTTP-диагностика приложения продолжает
работать. **Проверка видимости** показывает защиту текущего туннеля и необходимость
переподключения. Это статус сеанса, а не проверка атаки из другого приложения;
он не скрывает VPN-интерфейсы и другие системные признаки VPN.
