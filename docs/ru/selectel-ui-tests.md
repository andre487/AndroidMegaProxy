# UI-тесты Selectel

Workflow `Selectel UI` запускается **только вручную**: Actions → Selectel UI → Run workflow,
выбрать ветку PR и один из независимых профилей. Пуши не арендуют устройства.

- `required`: HONOR X8c / Android 15 (API 35), 12 тестовых случаев. Проверка `Selectel UI required`
  обязательна для текущего коммита PR; после нового коммита нужен новый ручной прогон, если полный diff PR затрагивает Android.
- `additional`: Galaxy A03 / Android 11, Galaxy A14 / Android 13, Galaxy A35 / Android 16,
  Pixel 8 / Android 17 — четыре устройства, 48 тестовых случаев. Проверка `Selectel UI additional`
  необязательна. Она не повторяет конфигурацию required и не заменяет его обязательный статус.

Список зафиксирован в `config/selectel-devices.json` по каталогу на 2026-09-07. Оба профиля используют
ARM64. Дополнительные устройства запускаются максимум по два одновременно в GitHub и последовательно
локально. Автоматического обнаружения и подмены недоступных конфигураций нет; список меняется через PR.
Ошибка сборки, любого выбранного устройства или освобождения аренды приводит к ошибке профиля.
Native/Python/Android проверки запускаются автоматически, если нужны по полному diff PR. Профили UI запускаются отдельно;
для слияния достаточно успешного required.

```sh
gh workflow run selectel-ui.yml --ref YOUR_PR_BRANCH -f devices=required
# Или: -f devices=additional
```

Можно выбрать только ветку этого репозитория; код форков автоматически не получает секреты.
Эмулятор и release-подпись не используются. Ruleset для `main` требует `Selectel UI required` от
GitHub Actions вместе с существующими native/Android проверками. Кнопка ручного запуска появится
в Actions после попадания workflow в основную ветку.

Результаты UI публикуются как статусы коммита, а не только проверки ручного workflow. Для каждого
коммита PR, затрагивающего Android, обычный CI создаёт ожидающий `Selectel UI required` со ссылкой на ручной запуск. Начало
и окончание профиля обновляют его собственный статус на проверяемом SHA. Повтор CI сохраняет
существующие UI-результаты. Новый коммит не наследует успех UI-тестов предыдущего коммита.

CI анализирует **полный diff PR относительно базы**, а не только последний пуш. Изменения только
Python запускают Python-проверки; изменения только документации пропускают тестовые задания. Если
Android не затронут, Android- и UI-тесты пропускаются, обязательный UI-статус становится успешным
с пояснением. Ручной UI-запуск применяет тот же фильтр: без сборки APK и аренды. Общие файлы CI/сборки
и неизвестные пути консервативно включают все проверки. `Change scope` — обязательная проверка.

## Интерактивный запуск GitHub Actions

```sh
python3 scripts/github_actions.py
# Проверить выбор без запуска заданий и аренды устройств:
python3 scripts/github_actions.py --dry-run
```

Выберите открытый PR, затем UI `required`, UI `additional` или повтор обычного CI. Скрипт показывает параметры
ветки и текущий коммит, спрашивает перед отправкой и прекращает запуск, если PR изменился за время
выбора. При UI-запуске GitHub берёт коммит ветки в момент принятия запроса; не делайте пуш одновременно
с запуском. Повтор CI использует только существующий завершённый прогон текущего коммита PR.
PR из форков исключены. Release-workflow в меню нет. `q` или Ctrl+C отменяет операцию.

`--yes` / `-y` пропускает последнее подтверждение, сохраняя выбор PR/профиля и проверку,
что коммит PR не изменился. При сочетании с `--dry-run` запусков по-прежнему нет.

Python-код использует только стандартную библиотеку и вызывает **GitHub CLI (`gh`)**. Установите `gh`
и один раз выполните `gh auth login` либо используйте его авторизацию через `GH_TOKEN`/`GITHUB_TOKEN`.
Своего HTTP-клиента и хранения токенов у скрипта нет. Он вызывает `gh pr list/view`, `gh workflow run`
и `gh run list/rerun` массивами аргументов, без shell. Локальные секреты Selectel и Android toolchain
не нужны. Другой репозиторий задаётся через `--repo OWNER/REPO`. В списке до 1 000 открытых PR.
Ошибка или таймаут запуска не приводят к повторной отправке: сначала проверьте Actions.
Для нашего зарегистрированного workflow скрипт работает и до появления кнопки Run workflow.

## Настройка

Создайте сервисного пользователя Selectel с ролью `mobile_farm.admin` в выбранном проекте. Роль
нужна для добавления и удаления платных устройств, а не только открытия ADB-сессий. В GitHub Actions
задайте secrets: `SELECTEL_USERNAME`, `SELECTEL_PASSWORD`, `SELECTEL_ACCOUNT_ID`, `SELECTEL_PROJECT_ID`.
В `SELECTEL_PROJECT_ID` нужен UUID проекта, не его отображаемое имя.

Локально положите присваивания этих переменных shell в `~/.config/megaproxy/selectel.env`: права
каталога 700, файла 600. Обёртка загружает его только вне GitHub Actions. Другой путь задаётся через
`MEGAPROXY_SELECTEL_ENV`. Не загружайте `release.env` для UI-тестов.
Нужны Python 3 и Android SDK platform-tools (ADB); отдельный Selectel CLI и зависимости pip не нужны.
Перед сборкой настройте обычный toolchain проекта: JDK 21, SDK, NDK, Go и Ruby.

```sh
bundle exec fastlane android selectel_probe
bundle exec fastlane android ui_test_artifacts
bundle exec fastlane android selectel_ui_tests
```

Первая команда только читает данные. Последняя арендует **одно устройство с поминутной оплатой**.
По умолчанию выбирается HONOR X8c, Android API 35, arm64. Можно задать
`SELECTEL_ANDROID_API` и `SELECTEL_DEVICE_MODEL` (точное имя модели из каталога). Автоматической смены
модели или API нет. Доступность и фактическая цена зависят от провайдера. APK собираются до начала аренды и содержат только ARM64, чтобы сократить время загрузки.
ADB использует отдельные ключи и порт сервера 5038 (переопределяется `SELECTEL_ADB_PORT`), поэтому
локальные телефоны и эмуляторы не затрагиваются.

Перед созданием аренды скрипт ждёт свободное устройство до **600 секунд**, проверяя наличие
каждые 30 секунд. `SELECTEL_DEVICE_WAIT_SECONDS` принимает 0–900 секунд (0 — одна проверка сразу).
Ожидание не создаёт аренду и не оплачивается как использование устройства. Ошибки API завершают
прогон сразу; запрос аренды с неопределённым результатом не повторяется. Между проверкой наличия
и арендой устройство всё ещё может занять другой пользователь. Лимит задания увеличен до 40 минут,
чтобы после ожидания осталось время на тесты и освобождение устройства.

## Дополнительные устройства локально

```sh
bundle exec fastlane android ui_test_artifacts profile:additional
bundle exec fastlane android selectel_ui_tests profile:additional
```

Для обеих команд нужен `profile:additional`. Выбранный каталог использует ARM64; если позднее явно добавить
в список ARM32, сборка переключится на универсальный APK. Локально устройства
запускаются последовательно; журналы аренды и отчёты разделены по ID из каталога. Ошибки тестов
не останавливают остальные конфигурации; ошибка освобождения аренды прекращает новые аренды.
Сводка — `app/build/reports/selectel/matrix.json`. `selectel_release` повторяет освобождение для всех
журналов в `.selectel/`, включая скачанные в отдельные подкаталоги артефактов.

## Покрытие и результаты

Тесты работают с настоящей activity, навигацией и хранилищем профилей, используют синтетические данные
и не включают VPN. Проверяются меню главного экрана, состояние после пересоздания activity, сохранение
отредактированного профиля и закрытие нетронутого черновика. Матрица: русский/английский и шрифт
100%/200%. Исходный масштаб восстанавливается после каждого теста. Существующие устройства проекта
Selectel не изменяются.

Результаты сохраняются в `app/build/reports/selectel/`: JUnit XML, вывод instrumentation и скриншоты
главного экрана. Успешного кода возврата ADB недостаточно: отсутствие тестов, падение runner, ошибки
проверок и таймауты завершают job ошибкой. GitHub публикует отчёты и ссылку в summary.

## Освобождение аренды

`.selectel/lease.json` содержит идентификаторы проекта, устройства, слота и временного публичного
ключа, но не секреты. Не удаляйте его до завершения аренды. Файл переживает Gradle clean и исключён
из Git. `selectel_ui_tests` освобождает аренду в `finally`; в GitHub также есть шаг с `always()`.
Повторное освобождение безопасно: проверяется ID слота, чтобы старый журнал не удалил новую аренду.

```sh
bundle exec fastlane android selectel_release
```

Отключение ADB или освобождение устройства пользователя **не останавливает оплату**: нужно удалить
устройство из проекта. Workflow `Selectel lease recovery` после завершения прогона читает сохранённый
артефакт журнала и освобождает оставшуюся аренду кодом из доверенной основной ветки. Он начинает
работать после слияния в основную ветку и не выполняет код из скачанных артефактов.
Для ручного восстановления в другом checkout скачайте артефакт `selectel-lease-*`, положите его
`lease.json` в `.selectel/` и запустите `selectel_release`.


При отмене работают шаг освобождения с `always()` и отдельный recovery-прогон по
`workflow_run: completed`, включая результат `cancelled`. Recovery также закрывает статус ошибки
или отмены, не перезаписывая более новый прогон. Время локального cleanup ограничено: GitHub может
принудительно остановить отменяемые процессы через пять минут. Force-cancel и потеря runner могут
обойти локальное освобождение. Recovery нужен загруженный журнал; он начнёт автоматически работать
только после попадания workflow в основную ветку.

Остаётся окно риска: runner может погибнуть до загрузки журнала, а API — создать аренду, но потерять
ответ. Поэтому запрос создания автоматически не повторяется. При `allocation_pending` проверьте
проект в панели Selectel и удалите именно новую аренду. Не удаляйте все устройства: они могут быть
заняты другими задачами. В журнале сохраняется список устройств до аренды для проверки. Ошибка API
или сети при очистке завершает job ошибкой и сохраняет журнал для повторной попытки. При жёстком
завершении процесса гарантировать локальную очистку невозможно.
