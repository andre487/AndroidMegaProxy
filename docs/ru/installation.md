## Установить и подключиться

**GitHub:** откройте APK на телефоне через уведомление браузера или Файлы → Загрузки.
По запросу разрешите **Установку неизвестных приложений / Разрешить из этого источника**
браузеру/файловому менеджеру, затем Установить → Открыть. После установки разрешение можно отозвать.
Если мешает Samsung Auto Blocker, см. [инструкцию Samsung](https://www.samsung.com/us/support/answer/ANS10003636/).
Ограничения рабочего устройства снимает администратор.

**F-Droid:** установите [клиент F-Droid](https://f-droid.org/), обновите каталог, откройте ссылку
выше или найдите MegaProxy (`net.megaproxy487`) и установите. При запросе Android разрешите
установку приложений из F-Droid.

В MegaProxy разрешите уведомления для управления соединением, добавьте/импортируйте профиль,
выберите глобальную маршрутизацию или приложения и нажмите **Подключиться**. Подтвердите запрос VPN.
**Тест**, **Скорость**, **Видимость VPN** — отдельные экраны главного меню. Заметный переключатель
MegaProxy в split routing и галочка приложения меняют один выбор; upstream sockets защищены от зацикливания.

## Безопасное обновление

Используйте **Настройки → Обновления приложения** или исходный установщик. Ежедневные проверки
включены; скачивание требует согласия. Источник, недельные напоминания, пропуск версий: [Обновления](updates.md).
Устанавливайте поверх старой версии; **не удаляйте приложение** ради исправления ошибки:
это удаляет локальные профили/настройки/SSH pins. Перед миграцией экспортируйте нужную конфигурацию
и защищайте экспортированные секреты.

Для обновления нужны тот же package, совместимая подпись, правильный ABI и допустимый version code.
Сохраняйте вариант APK: коды ABI-specific выше universal того же релиза. Переходу на universal
может понадобиться более новый релиз. Debug/другой дистрибьютор могут иметь другую подпись;
не форсируйте downgrade и не удаляйте работающую установку.

## Варианты APK и проверка

[Assets релиза](https://github.com/andre487/AndroidMegaProxy/releases/latest) содержат отдельные APK:

| Файл | Устройство |
| --- | --- |
| `mega-proxy-universal.apk` | Рекомендуется, если сомневаетесь; все ABI |
| `mega-proxy-arm64-v8a.apk` | 64-битные ARM-телефоны |
| `mega-proxy-armeabi-v7a.apk` | 32-битный ARM |
| `mega-proxy-x86_64.apk` | 64-битные x86 устройства/эмуляторы |
| `mega-proxy-x86.apk` | 32-битные x86 устройства/эмуляторы |

Source ZIP, старые AAB и архивы символов не устанавливаются. Скачайте `SHA256SUMS` того же релиза
и сравните полный hash с `shasum -a 256 FILE.apk` (macOS), `sha256sum FILE.apk` (Linux)
или `Get-FileHash FILE.apk -Algorithm SHA256` (PowerShell). Совпадение выявляет повреждение загрузки,
но не доказывает подлинность независимо. Раздел **VirusTotal** релиза содержит ссылки на отчёты
конкретных хешей; отсутствие детектов не гарантирует безопасность.

Необязательный [ADB](https://developer.android.com/tools/adb#move): включите USB debugging,
авторизуйте компьютер, проверьте `adb devices`, затем `adb -s SERIAL install -r FILE.apk`.
После работы отладку можно отключить.

## Тестовые APK из PR

В описании PR и summary Android-задания есть ссылки на артефакты со сроком 14 дней. Нужны
авторизация GitHub и доступ. Распакуйте `megaproxy-pr-<number>-debug-apk`, установите `app-debug.apk`
на запасное устройство/эмулятор: package совпадает с релизом, подпись другая и может меняться между
CI-запусками. Не удаляйте повседневный релиз ради теста. Unsigned-release артефакт служит проверке
сборки и не устанавливается как подписанный релиз. Пропущенная сборка не публикует новый APK.

## Ошибки установки

| Симптом | Что проверить |
| --- | --- |
| Конфликт package / downgrade | Подпись и вариант/версию; нужен совместимый новый релиз |
| Нет подходящего ABI | Universal или правильную архитектуру; Android 8+ |
| Ошибка разбора | APK вместо ZIP/AAB, checksum и полноту загрузки |
| Мало места / ADB unauthorized | Свободное место / разблокировку и авторизацию компьютера |
| Установилось, но не подключается | Профиль/сервер/пароли, сеть и разрешение VPN |
